Aufgabe: Performance-Optimierung der Admin-Ansicht (Featured Matches Tab) durch serverseitige Pagination & Suche.

Problem:
Bislang übertrug GET /api/admin/matches/featured ungefiltert alle 27.000+ Featured Matches (33 MB Payload, 12 Sekunden Ladezeit), wodurch der Browser einfror.

Anforderungen:
1. Backend (apps/backend/src/app/scraper/admin.controller.ts & admin.service.ts):
   - Aktualisiere GET /api/admin/matches/featured:
     * Query-Parameter:
       - page: number (default: 1, min: 1)
       - limit: number (default: 25, min: 1, max: 100)
       - query: string (optional, durchsucht homeTeam.name, guestTeam.name, leagues.name oder matches.id)
     * Rückgabe:
       {
         data: Match[],
         total: number,
         page: number,
         limit: number,
         totalPages: number
       }
     * Nutze SQL COUNT(*), LIMIT und OFFSET in Postgres, sodass die Abfrage in unter 50ms antwortet.
2. Shared Types (libs/shared-types/src/lib/basketball.types.ts):
   - Ergänze das Interface:
     export interface PaginatedMatchesResponse {
       data: Match[];
       total: number;
       page: number;
       limit: number;
       totalPages: number;
     }
3. Frontend (apps/frontend/src/components/admin/AdminDashboard.tsx):
   - Featured Matches Tab umstellen:
     * Ruft /api/admin/matches/featured?page={page}&limit=25&query={debouncedQuery} auf.
     * Unterstützt Paginierungs-Steuerung (Vorherige Seite, Nächste Seite, "Seite X von Y", Gesamtanzahl Treffer).
     * Das Suchfeld triggert debounced die serverseitige Suche und springt auf Seite 1 zurück.
     * Beim Hinzufügen / Entfernen eines Featured Matches wird die aktuelle Seite neu geladen.
4. Unit-Tests:
   - Passe apps/backend/src/app/scraper/admin.controller.spec.ts an und teste die Pagination + Suchfilterung.
